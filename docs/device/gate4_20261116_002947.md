### The accounting trap (do not quote `smaps` for a GPU process)

For the same PID the two sources disagree by **2.94×**: `smaps_rollup` says 84,578 kB, `dumpsys meminfo` says 248,729 kB. The difference is the **GL mtrack** row (164,192 kB) — the Mali driver's own accounting of the CL buffers this process owns, which never appears in `/proc/<pid>/smaps`. Gate 4 therefore uses the `dumpsys` TOTAL PSS (the larger, conservative number); the smaps figure is recorded only as the cross-check.
